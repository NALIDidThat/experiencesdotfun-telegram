Build a minimal, modern Telegram Mini App for **Experiences.fun**.

Experiences.fun is a platform for discovering and participating in real-world educational, environmental and community volunteering experiences.

The MVP should focus specifically on one core loop:

**Organisations publish experiences → participants discover them → participants join → participants complete the experience → the organisation verifies completion → the participant receives XP and/or a monetary reward.**

## PRODUCT PRINCIPLES

Build this as a **Telegram-native experience**, not as a conventional web dashboard squeezed inside Telegram.

The interface should be:

* Minimal
* Modern
* Mobile-first
* Fast
* Extremely easy to understand
* Clean and spacious
* Friendly without feeling childish
* Community-oriented
* Designed primarily for Telegram Mini App dimensions

Avoid unnecessary complexity.

Do not introduce crypto terminology unless required by the functionality.

Do not make users connect a wallet during initial onboarding.

The product should feel like a modern combination of:

* local volunteering marketplace
* community discovery platform
* lightweight rewards system

## USER TYPES

There are two primary user types.

### 1. PARTICIPANT

A participant can:

* create a profile
* select interests
* set their location
* discover volunteering experiences
* view experience details
* join an experience
* see instructions
* attend/complete the activity
* submit completion/proof
* wait for host verification
* receive XP
* receive a monetary reward where applicable
* view their completed experiences
* view their earned rewards

### 2. ORGANISATION / HOST

An organisation can:

* create an organisation profile
* provide organisation information
* request/receive verification
* publish volunteering experiences
* define requirements
* define capacity
* define date/time/location
* define XP reward
* optionally define monetary reward
* manage participants
* mark participants as attended/completed
* verify submitted completion
* trigger participant rewards
* view basic impact statistics

## IMPORTANT PRODUCT LOOP

The most important interaction in the application is:

**Discover → Join → Participate → Verify → Reward**

Every screen should ultimately support this loop.

Do not optimise for feature count.

Optimise for:

* time to first experience
* number of experiences joined
* completion rate
* verification rate
* reward distribution
* repeat participation

## VERIFICATION

Verification is one of the most important features in this MVP.

Participants should not automatically receive rewards simply because they clicked "Complete".

The host must verify completion.

Participant flow:

**Join → Attend → Submit completion → Await verification**

Host flow:

**Participant submits → Host reviews → Host verifies/rejects**

Once verified:

**Completion verified ✓**

Then automatically trigger the configured reward.

## REWARDS

Support two reward types:

### XP

XP is the default reward mechanism.

Example:

**+150 XP**

XP contributes to the participant's profile and progression.

### Money

Hosts can optionally attach a monetary reward.

Example:

**£20**

The MVP should model this reward clearly even if actual payment processing is initially handled manually.

Do not build a complicated financial infrastructure unless required.

## WHAT NOT TO BUILD YET

Do not prioritise:

* token launch
* token trading
* complex wallet management
* DAO functionality
* sophisticated AI
* social feeds
* complex leaderboards
* NFT systems
* advanced analytics
* complicated payment infrastructure
* enterprise permissions

The goal is to prove that organisations will create real volunteering opportunities and that people will actually participate in them.

## SUCCESS CRITERIA

The MVP is successful if a new participant can:

**Open Telegram → onboard → discover an experience → join it**

and an organisation can:

**sign up → create an experience → manage participants → verify completion → issue a reward**

without needing human intervention from the Experiences.fun team for every individual action.

Build the product around this loop first.
