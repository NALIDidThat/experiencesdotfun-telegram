## TELEGRAM BOT + MINI APP INTEGRATION

Experiences.fun should not function only as a Mini App embedded inside Telegram.

The Telegram bot should act as a lightweight command and notification layer around the application.

Use the Mini App for rich interfaces and the Telegram bot for quick actions, status checks, social interactions and notifications.

The goal is:

**Mini App = full product**

**Telegram Bot = quick command interface + notifications**

---

# TELEGRAM COMMANDS

Implement a basic Telegram bot command system.

Commands should be simple, memorable and useful.

## /start

When a user first interacts with the bot:

Display:

**Welcome to Experiences.fun 🌍**

Discover real-world experiences, volunteer with your community and earn XP and rewards.

Buttons:

**Open Experiences.fun**

**My Progress**

**Explore Experiences**

If the user has not completed onboarding, `/start` should open the onboarding flow in the Mini App.

---

## /help

Display the available commands:

**Experiences.fun commands**

`/experiences` — Discover current experiences

`/requests` — View pending friend requests

`/profile` — View your profile

`/help` — View available commands

Use Telegram inline buttons wherever possible.

When the recipient presses:

**Accept**

Update the backend relationship.

Then notify both users.

# TELEGRAM NOTIFICATION EVENTS

The backend should support Telegram notifications for important events.

At minimum:

### Participant events

* Friend request received
* Friend request accepted
* Experience joined
* Experience reminder
* Experience cancelled
* Experience completed
* Completion verified
* Reward issued

### Host events

* New participant joined
* Experience approaching capacity
* Participant submitted completion
* Verification required
* Experience completed
* Experience summary available

Avoid excessive notifications.

Notifications should only be sent when they represent a meaningful action or state change.

# SHARED USER IDENTITY

The Telegram account should be the primary identity layer for the MVP.

Use the Telegram user ID as the stable identifier.

The backend user model should associate:

* Telegram ID
* Telegram username
* Experiences.fun profile
* participation history
* XP
* friendships
* organisation relationships

Do not create unnecessary duplicate authentication flows.

---

# SOCIAL GRAPH DATA MODEL

Add a friendship model.

### Friendship

* id
* requester_user_id
* recipient_user_id
* status
* created_at
* accepted_at

Possible statuses:

**pending**

**accepted**

**declined**

**blocked**

A friendship should only become active after the recipient accepts.

Prevent:

* duplicate requests
* self-friend requests
* repeated requests while one is pending
* friendship duplication

---

# TELEGRAM BOT SECURITY

Do not trust Telegram usernames alone as authentication.

Verify Telegram user identity using Telegram's Mini App authentication/init data.

The backend should associate commands and actions with the authenticated Telegram user ID.

Never allow a user to manipulate another user's:

* XP
* rewards
* experience participation
* friendships
* verification status

Only authorised organisation hosts can verify participant completion.

---

# BOT DESIGN PRINCIPLE

The Telegram bot should remain lightweight.

Do not attempt to recreate the entire Mini App through chat commands.

Use Telegram for:

**Check → Notify → Act → Open**

Use the Mini App for:

**Discover → Explore → Create → Manage → Review**

This keeps the bot useful without turning it into a horrible text-based ERP system.

# SUCCESS CRITERIA FOR TELEGRAM INTEGRATION

A participant should be able to:

**Open Telegram → discover an experience → join → receive reminders → complete → get verified → receive XP/reward**

without needing to leave Telegram.

A participant should also be able to:

**send a friend request → receive acceptance → discover experiences together**

An organisation should be able to:

**receive participant notifications → review completions → verify contribution → trigger rewards**

The Telegram bot and Mini App should feel like one unified Experiences.fun product rather than two separate systems.
