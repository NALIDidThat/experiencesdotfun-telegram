# 2. PRIMARY OBJECTIVE

Implement a new Telegram-native Community Contribution system.

The Experiences.fun bot must be able to:

1. Be added normally to a Telegram group.
2. Receive ordinary group messages.
3. Identify the Telegram user who sent each message.
4. Associate that Telegram user with an Experiences.fun user.
5. Determine whether the message qualifies for Community XP.
6. Award Community XP in real time.
7. Store contribution events in PostgreSQL.
8. Calculate each user's rank within that specific Telegram community.
9. Allow users/admins to check ranks directly inside the Telegram group.
10. Synchronise all contribution data with the Experiences.fun Mini App.
11. Display community contribution and reputation data inside the Mini App.
12. Keep Community XP conceptually separate from existing Experience XP.

The final system should feel like:

Telegram Group
↓
Experiences.fun Bot
↓
Message received
↓
Contribution Engine
↓
Qualification + anti-abuse checks
↓
Contribution Event recorded
↓
Community XP updated
↓
Rank recalculated dynamically
↓
Telegram `/rank`
↓
Experiences.fun Mini App

# 8. MVP COMMUNITY XP RULE

Implement the initial Community XP rule exactly as follows:

### QUALIFYING MESSAGE

A message receives:

```text
+1 Community XP
```

if it contains:

```text
7 or more words
```

Examples:

```text
"hello"
= 0 XP
```

```text
"this is a useful community experience"
= 1 XP
```

```text
"this is a really useful experience for our community"
= 1 XP
```

Use whitespace-aware word counting.

A reasonable implementation is:

```ts
function countWords(text: string): number {
    return text.trim().split(/\s+/).filter(Boolean).length;
}
```

Then:

```ts
countWords(message.text) >= 7
```

means the message qualifies.

---

# 9. NON-QUALIFYING MESSAGES

The following should receive 0 Community XP:

### Commands

```text
/rank
/xp
/help
/start
etc.
```

### Empty messages

No text = no XP.

### Bot messages

Ignore messages generated by bots.

### Messages below 7 words

```text
6 words or fewer = 0 XP
```

### Duplicate messages

If the same user sends the exact same message repeatedly, do not reward unlimited XP for identical spam.

At minimum, detect duplicate content within a reasonable recent window.

# 10. ANTI-SPAM PROTECTION

Implement basic anti-abuse protection in the MVP.

Do NOT build an unnecessarily complicated AI moderation system yet.

The MVP needs simple deterministic rules.

Implement:

### Rule 1: Commands

Commands earn:

```text
0 XP
```

### Rule 2: Bots

Bot messages earn:

```text
0 XP
```

### Rule 3: Duplicate messages

Repeated identical messages should not repeatedly generate XP within a short time period.

### Rule 4: Rate limiting

Prevent obvious message farming.

For example:

```text
Maximum 20 qualifying messages per minute
```

After that threshold:

```text
additional messages = 0 XP
```

Do not delete the user's messages.

Simply do not award XP.

### Rule 5: Daily cap

Implement a configurable daily Community XP cap.

Initial default:

```text
100 Community XP per user per group per day
```

This should be configurable rather than hard-coded throughout the application.

# 24. RANK CALCULATION

Do not permanently store rank numbers.

Rank should be dynamically calculated from current Community XP.

Conceptually:

```text

```

2. Higher number of qualifying contributions
3. Earlier achievement of that XP

The rank should therefore be stable and predictable.

                │              │              │

                 ┌─────────────┴─────────────┐
                 │                           │
          Telegram Mini App             Telegram Bot
