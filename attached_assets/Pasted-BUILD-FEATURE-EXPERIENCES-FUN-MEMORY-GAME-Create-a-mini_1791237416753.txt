BUILD FEATURE: EXPERIENCES.FUN MEMORY GAME

Create a minimal, polished memory game inside Experiences.fun inspired by the visual simplicity and gameplay flow of the reference game "Impulse".

IMPORTANT:
- Use the uploaded reference screenshots as visual inspiration.
- DO NOT copy the artwork, branding, typography, or exact UI.
- Recreate the underlying interaction pattern using Experiences.fun's own visual identity.
- Replace ghosts with cute, minimal ASTRONAUT characters.
- The game should feel native to Experiences.fun, not like an embedded third-party game.

==================================================
1. CORE GAME CONCEPT
==================================================

The player is shown a grid of tiles.

Some tiles contain astronauts.

The player has a short amount of time to memorize which tiles contain astronauts.

The tiles then flip/hide.

The player must tap the tiles that previously contained astronauts.

If all astronaut positions are selected correctly, the player completes the level and receives +5 XP.

After completing a level, the next level becomes progressively harder by increasing the number of tiles and/or astronaut positions.

The goal is to test and improve memory.

Core loop:

SEE → MEMORIZE → HIDE → RECALL → COMPLETE → +5 XP → NEXT LEVEL

4. MEMORIZATION PHASE
==================================================

The astronaut positions are revealed for a limited amount of time.

The player has a maximum of 3–5 seconds to memorize the positions.

Use the following timing system:

LEVEL 1:
5 seconds

LEVEL 2:
5 seconds

LEVEL 3:
4 seconds

LEVEL 4:
4 seconds

LEVEL 5:
3.5 seconds

LEVEL 6:
3 seconds

LEVEL 7:
3 seconds

The timer should be visually obvious but not distracting.

Example:

"Remember..."

[████████████████░░░]

3.2s

When the timer reaches zero, all tiles flip over.


==================================================
5. RECALL PHASE
==================================================

After the memorization timer ends:

- Hide all astronauts.
- Flip all tiles to their hidden state.
- Change the instruction to:

"Tap the astronaut tiles"

The user can now tap tiles.

Selected tiles should receive a clear visual state.

Example:

UNSELECTED:
Dark tile

SELECTED:
Highlighted tile with a subtle confirmation indicator.

Do NOT immediately reveal the astronaut after each tap.

The player should have to rely entirely on memory.


==================================================
6. ANSWER VALIDATION
==================================================

The player must correctly select EVERY tile that previously contained an astronaut.

Rules:

- Selecting a correct tile = correct.
- Selecting an incorrect tile = mistake.
- Missing an astronaut tile = incomplete answer.
- Selecting an incorrect tile should trigger a short visual error state.
- The game should then reveal the correct answer briefly.

If the player succeeds:

Show:

"Level complete!"

Then:

"+5 XP"

Then automatically transition to the next level after a short delay.

If the player fails:

Show:

"Not quite"

Then briefly reveal the correct astronaut positions.

Provide a CTA:

"Try again"

Retrying the level should NOT award XP.

XP is awarded only once when the level is successfully completed.


==================================================
7. XP SYSTEM
==================================================

Every successfully completed level awards:

+5 XP

Example:

Level 1 complete
+5 XP

Level 2 complete
+5 XP

Level 3 complete
+5 XP

etc.

XP must be persisted using the existing Experiences.fun XP/reward system.

IMPORTANT:

Do not simply modify a frontend XP counter.

The XP reward must use the application's existing backend/database XP mechanism so users cannot refresh/reload the game to repeatedly claim XP.

Each successful level completion should generate a unique completion/reward event.

Prevent duplicate XP claims for the same level attempt.

18. XP / USER DATA

Persist:

- Current level
- Highest level completed
- Total XP earned from this game
- Completed levels
- Game attempts
- Last played timestamp

Do NOT trust client-side XP values.

All XP awards must be validated server-side.

Recommended backend event:

memory_game_level_completed

Payload:

{
  userId,
  gameId,
  level,
  xpAwarded: 5,
  timestamp,
  attemptId
}

Use an idempotency mechanism so the same completion event cannot award XP twice.

==================================================
25. PRODUCT PRINCIPLE
==================================================

The game is not intended to be a standalone arcade game.

It exists to make learning, cognitive development and contribution inside Experiences.fun more engaging.

The experience should follow this principle:

LOW FRICTION
+
SHORT SESSION
+
CLEAR CHALLENGE
+
IMMEDIATE FEEDBACK
+
MEANINGFUL REWARD

The user should be able to open the game, play a level, earn 5 XP and leave within approximately 30–60 seconds.

The game should make users want to replay because they want to improve their memory and progress their Experiences.fun profile, not because the UI is aggressively trying to manipulate them.

Build the first version cleanly and modularly so additional cognitive games can later use the same underlying game/reward infrastructure.
